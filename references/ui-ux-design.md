# UI/UX Design

## Purpose and boundaries

Design usable, understandable, inclusive digital experiences. UI/UX defines user needs, information architecture, flows, interaction behavior, interface specifications, and design-system rules. Web/application development implements the software; game design owns game mechanics and progression.

## 1. Discovery

Understand the users, tasks, context, platform, constraints, and success criteria. Identify primary journeys, user skill levels, accessibility needs, device and input conditions, network limitations, and relevant business or learning goals. Use research proportionate to risk: interviews, observation, analytics, support feedback, competitive review, or lightweight validation. Do not invent research findings.

## 2. Information architecture

Organize content around user goals. Define navigation hierarchy, labels, categories, search and filtering needs, page/screen inventory, and content relationships. Prefer familiar language and predictable structure. Avoid unnecessary depth, duplicate destinations, ambiguous labels, and hidden essential actions.

## 3. User flows and interaction

Map the key journeys from entry to completion, including:
- Initial, loading, empty, success, error, and offline states.
- Validation, confirmation, cancellation, and recovery.
- Permissions and destructive actions.
- Keyboard, touch, pointer, and assistive-technology interaction where relevant.
- Returning users, persistence, and interrupted sessions.

Make system status visible. Provide feedback after actions and prevent avoidable errors. Use confirmations for consequential actions, not every routine interaction. Ensure controls have clear labels and predictable behavior.

## 4. Wireframes and prototypes

Start with low-fidelity structure when requirements are uncertain. Progress to detailed layouts and interactive prototypes when visual or behavioral validation is needed. Label prototype assumptions and simulated behavior; do not present a nonfunctional prototype as a working product.

Validate important tasks with representative users when feasible. Observe whether users can understand the interface and complete tasks without coaching. Prioritize issues by impact and frequency.

## 5. Visual interface design

Establish hierarchy, spacing, alignment, color, typography, iconography, imagery, and component behavior. Design for real content lengths, localization, dynamic data, and different screen sizes. Keep primary actions distinguishable and maintain consistent control behavior.

Define reusable components and tokens where a system is useful: color, type scale, spacing, radii, elevation, grid, breakpoints, and interaction states. Document exceptions rather than allowing arbitrary one-off styles.

## 6. Responsive and adaptive behavior

Design for relevant viewport sizes and input modes rather than scaling a desktop layout blindly. Define breakpoints or content-driven layout changes, navigation transformation, overflow behavior, touch target sizing, safe areas, orientation behavior, and minimum supported dimensions.

Test both narrow and wide screens, long content, zoom, and text scaling where applicable. Do not claim universal device compatibility without testing.

## 7. Accessibility

Use semantic structure, meaningful labels, logical focus order, visible focus, keyboard access, sufficient contrast, text alternatives, captions/transcripts, and non-color status cues as relevant. Avoid interaction that depends only on hover, color, sound, or precise gestures. Respect reduced-motion preferences and avoid flashing content. Apply an appropriate accessibility standard when the project specifies one.

## 8. Motion and feedback

Use motion to communicate state, spatial relationships, continuity, and feedback. Keep transitions purposeful, brief, and consistent. Avoid motion that delays tasks, distracts, or causes discomfort. Provide reduced-motion behavior where appropriate.

## 9. Handoff and implementation

Provide annotated screens, component states, responsive rules, interaction flows, assets, typography, spacing/color tokens, content guidance, and acceptance criteria. Specify edge cases and behavior, not just ideal screenshots. Coordinate with developers when implementation constraints require a design adjustment.

## 10. UX and interface QA

Check task completion, navigation clarity, labels, hierarchy, consistency, responsiveness, keyboard operation, focus, contrast, touch targets, error recovery, empty/loading states, localization, and performance perception. Test in the implemented product where available; record environment and limitations.

## Deliverables

Depending on scope: research summary, user journeys, information architecture, flow diagrams, wireframes, prototypes, screen specifications, component library, design tokens, assets, responsive rules, accessibility notes, and implementation handoff.

## Definition of done

The key user tasks and states are specified, interface behavior is understandable, responsive and accessibility requirements are addressed, implementation handoff is actionable, and relevant usability and interface checks are recorded.
